Stack & Queue PHẦN 2

LIFO (Stack) và FIFO (Queue) — cấu trúc nền + 10 bài toán trace tay.

1. Cấu trúc Stack

LIFO — Last In First OutVào sau ra trước. Như chồng đĩa — đặt lên trên, lấy từ trên.
#define MAX 100

struct Stack {
    int data[MAX];
    int top;
};

void khoitaoStack(Stack &s) { s.top = -1; }
bool rong(Stack s)  { return s.top == -1; }
bool day(Stack s)   { return s.top == MAX - 1; }

void push(Stack &s, int x) {
    if (!day(s)) s.data[++s.top] = x;
}

int pop(Stack &s) {
    if (!rong(s)) return s.data[s.top--];
    return -1;
}

int peek(Stack s) {
    if (!rong(s)) return s.data[s.top];
    return -1;
}

2. Cấu trúc Queue

FIFO — First In First OutVào trước ra trước. Như hàng đợi — vào từ rear, ra từ front.
struct Queue {
    int data[MAX];
    int front, rear;
};

void khoitaoQueue(Queue &q) { q.front = q.rear = -1; }
bool rongQ(Queue q) { return q.front == -1; }

void enqueue(Queue &q, int x) {
    if (q.rear == MAX - 1) return;
    if (rongQ(q)) q.front = q.rear = 0;
    else q.rear++;
    q.data[q.rear] = x;
}

int dequeue(Queue &q) {
    if (rongQ(q)) return -1;
    int x = q.data[q.front];
    if (q.front == q.rear) q.front = q.rear = -1;
    else q.front++;
    return x;
}

8. Ứng dụng thực tế

Stack Overflow — Đệ quy không có điểm dừng▾

Mỗi lần gọi hàm, hệ điều hành push một stack frame (chứa địa chỉ trả về, biến cục bộ) vào Call Stack. Khi hàm đệ quy không có điều kiện dừng, Call Stack bị push liên tục đến khi đầy → Stack Overflow.

Ví dụvoid f() { f(); } // push mãi không pop → crash
Undo/Redo (Ctrl+Z / Ctrl+Y) — Stack▾

Mỗi thao tác chỉnh sửa được push vào Stack_Back. Ctrl+Z → pop từ Stack_Back, push vào Stack_Forward. Ctrl+Y → pop từ Stack_Forward, push lại Stack_Back.

Thao tácStack_BackStack_Forward
Gõ "A"[A][]
Gõ "B"[A,B][]
Ctrl+Z[A][B]
Ctrl+Y[A,B][]

Phải dùng Stack (LIFO) vì cần hoàn tác theo thứ tự ngược lại với thứ tự thực hiện.

Print Spooler — Queue▾

Nhiều nhân viên gửi lệnh in cùng lúc. Máy in chỉ xử lý 1 lệnh tại thời điểm. Hệ thống dùng Queue (FIFO) để đảm bảo lệnh in nào đến trước được in trước — công bằng và đúng thứ tự.

Nếu dùng StackLệnh in đến sau sẽ được in trước (LIFO) → không công bằng → không thể dùng Stack.
BFS dùng Queue — DFS dùng Stack▾
BFS — Queue (FIFO)Duyệt theo từng lớp (level). Node hàng xóm được thêm vào cuối Queue → xử lý theo thứ tự gần nhất trước. Dùng tìm đường đi ngắn nhất, bạn bè chung mạng xã hội.
DFS — Stack (LIFO)Đi sâu theo một nhánh đến hết rồi mới quay lại. Node con được push vào Stack → pop ra xử lý tiếp. Dùng tìm đường trong mê cung, duyệt cây.
Keyboard Buffer — Queue▾

Khi gõ bàn phím nhanh, CPU chưa xử lý kịp. Các ký tự được lưu vào Queue (FIFO) → xuất hiện đúng thứ tự gõ trên màn hình.

Nếu dùng StackGõ "CTDL" → màn hình hiện "LDTC" (ngược chiều) → không thể dùng Stack.
Máy tính Casio — Stack▾

Máy tính bỏ túi chuyển biểu thức Infix → Postfix bằng Stack, rồi tính kết quả Postfix bằng Stack thứ hai. Nhờ đó xử lý đúng độ ưu tiên * / trước + - và ngoặc.

Trình biên dịch C++ — Stack kiểm tra ngoặc▾

Compiler dùng Stack để kiểm tra tính hợp lệ của { } trong code. Gặp { → push. Gặp } → pop và check. Nếu Stack không rỗng sau khi đọc hết file → báo lỗi "missing closing brace".

Cây nhị phân tự cân bằng — 4 phép xoay + thêm/xóa + 33 hàm đệ quy.

1. Khái niệm cơ bản

BF(node) = height(left) - height(right)
BFTrạng tháiHành động
-1, 0, 1Cân bằngKhông làm gì
+2Lệch tráiXoay LL hoặc LR
-2Lệch phảiXoay RR hoặc RL
Quy ước chiều caoNode null → height = -1. Node lá → height = 0.
struct AVLNode {
    int data;
    AVLNode *left, *right;
    int height;
};

int height(AVLNode* p) { return p ? p->height : -1; }
int BF(AVLNode* p) { return height(p->left) - height(p->right); }

void capnhatH(AVLNode* p) {
    p->height = 1 + max(height(p->left), height(p->right));
}

2. 4 Phép xoay — TRỌNG TÂM

Cách nhận dạng nhanhBF = +2 → lệch trái. Nhìn tiếp BF con trái: ≥ 0 → LL, < 0 → LR. BF = -2 → lệch phải. BF con phải: ≤ 0 → RR, > 0 → RL.
LLXoay phải — Right Rotation ▾
z y / xoay → / \ y x z / x
AVLNode* xoayphai(AVLNode* z) {
    AVLNode* y = z->left;
    AVLNode* T = y->right;
    y->right = z;
    z->left = T;
    capnhatH(z);
    capnhatH(y);
    return y;
}
RRXoay trái — Left Rotation ▾
z y \ xoay → / \ y z x \ x
AVLNode* xoaytrai(AVLNode* z) {
    AVLNode* y = z->right;
    AVLNode* T = y->left;
    y->left = z;
    z->right = T;
    capnhatH(z);
    capnhatH(y);
    return y;
}
LRXoay trái-phải — Left Right ▾
z z x / → / → / \ y x y z \ / x y
AVLNode* xoayLR(AVLNode* z) {
    z->left = xoaytrai(z->left); // bước 1: xoay trái con
    return xoayphai(z);            // bước 2: xoay phải gốc
}
RLXoay phải-trái — Right Left ▾
z z x \ → \ → / \ y x z y / \ x y
AVLNode* xoayRL(AVLNode* z) {
    z->right = xoayphai(z->right); // bước 1: xoay phải con
    return xoaytrai(z);              // bước 2: xoay trái gốc
}

}

AVLNode* them(AVLNode* root, int x) {
    if (root == nullptr) {
        AVLNode* p = new AVLNode{x, nullptr, nullptr, 0};
        return p;
    }
    if (x < root->data) root->left  = them(root->left,  x);
    else if (x > root->data) root->right = them(root->right, x);
    return canBang(root);
}

4. Xóa Node

Trường hợpXử lý
Node láXóa thẳng, trả nullptr
Có 1 conCon thay thế vị trí node
Có 2 conTìm inorder successor (min cây con phải), copy data, xóa node đó
AVLNode* timMin(AVLNode* p) {
    while (p->left) p = p->left;
    return p;
}

AVLNode* xoa(AVLNode* root, int x) {
    if (!root) return nullptr;
    if (x < root->data) root->left  = xoa(root->left,  x);
    else if (x > root->data) root->right = xoa(root->right, x);
    else {
        if (!root->left)  { AVLNode* t = root->right; delete root; return t; }
        if (!root->right) { AVLNode* t = root->left;  delete root; return t; }
        AVLNode* suc = timMin(root->right);
        root->data  = suc->data;
        root->right = xoa(root->right, suc->data);
    }
    return canBang(root);
}

4 kỹ thuật xử lý va chạm — tính tay ăn điểm + đủ 10 bài luyện tập.

Quy trình làm bài thi1. Xác định m. 2. Tính h(k). 3. Điền theo kỹ thuật. 4. Đánh dấu va chạm rõ ràng.

1. Chaining — Kết nối trực tiếp

Mỗi ô là một danh sách liên kết. Va chạm → nối vào cuối list tại ô đó.

2. Linear Probing — Dò tuyến tính

index = (h(k) + i) mod m    với i = 0, 1, 2...
Nhược điểmPhân cụm (Primary Clustering) — các phần tử dồn vào 1 vùng liên tiếp.

3. Coalesced — Kết nối hợp nhất

Mỗi ô thêm cột next. Va chạm → tìm ô trống từ cuối lên, nối con trỏ.

Hay nhầm khi thiTìm ô trống từ CUỐI bảng lên. Con trỏ next gán ở phần tử CUỐI CHAIN hiện tại.

4. Double Hashing — Băm kép

index = (h1(k) + i × h2(k)) mod m
Ưu điểmBước nhảy khác nhau cho từng key → phân tán đều hơn, tránh phân cụm.

7. Ứng dụng thực tế Hash Table

Cloud Deduplication — Google Drive▾

Khi upload file video 2GB, Google Drive không upload lại nếu file đã tồn tại. Cơ chế: tính hash SHA-256 của file → tra trong Bảng Băm (O(1)) → nếu đã có hash đó → bỏ qua, chỉ tạo liên kết. Tiết kiệm bandwidth và storage.

Tại sao không dùng cây BST?BST tìm kiếm O(log n) vs Hash Table O(1). Với hàng tỷ file trên Cloud, sự khác biệt rất lớn.
Facebook gợi ý kết bạn — Hash Table vs Nested Loop▾

Tìm bạn chung giữa user A (N bạn) và user B (M bạn):

  • Nested Loop: duyệt mọi cặp → O(N×M) — chậm với N,M = hàng nghìn
  • Hash Table: hash tất cả bạn của A → duyệt bạn của B, tra O(1) từng người → tổng O(N+M)
Ví dụ số liệuN=M=1000: Nested Loop = 1.000.000 phép so sánh. Hash Table = 2.000 phép so sánh. Nhanh hơn 500 lần!
DNS Cache — Hash Table vs Cây▾

DNS Cache lưu ánh xạ tên miền → IP. Mỗi request vào website đều tra DNS. Hash Table cho phép tra O(1) thay vì O(log n) của cây → giảm độ trễ mỗi lần duyệt web.

Bảo mật mật khẩu — SHA-256 một chiều▾

Website không lưu password dạng text mà lưu hash(password). Khi đăng nhập: tính hash của password nhập vào → so sánh với hash đã lưu. Hàm băm một chiều không thể đảo ngược → dù hacker lấy được database cũng không biết password gốc.

Tại sao không mã hóa 2 chiều?Mã hóa 2 chiều cần key → nếu mất key, mất luôn dữ liệu. Hash 1 chiều an toàn hơn cho password.
Redis Cache — Shopee giỏ hàng▾

Shopee lưu giỏ hàng của mỗi user trên Redis (Hash Table trên RAM). Key = user_id, Value = giỏ hàng. Tra cứu O(1), độ trễ ~1ms. So với database SQL trên disk: ~10-100ms. Với 10 triệu user đồng thời, sự chênh lệch này rất quan trọng.

Git — SHA-1 đánh nhãn Commit▾

Git dùng SHA-1 hash nội dung mỗi commit → tạo ra chuỗi 40 ký tự hex duy nhất (ví dụ: a1b2c3d4...). Bất kỳ thay đổi nào dù chỉ 1 ký tự đều tạo ra hash hoàn toàn khác → đảm bảo toàn vẹn lịch sử code.

Checksum file — MD5▾

Khi tải game/software, website cung cấp kèm MD5 hash. Sau khi tải xong, người dùng tính MD5 của file vừa tải → so sánh với MD5 gốc. Nếu khớp → file nguyên vẹn. Nếu khác → file bị lỗi hoặc bị can thiệp.

Load Balancing — Hash IP▾

Server nhận request → hash IP của client → mod số server → điều hướng vào đúng server đó. Đảm bảo cùng 1 client luôn vào cùng 1 server (session stickiness) và phân tán đều tải.

server_id = hash(client_IP) mod số_server
